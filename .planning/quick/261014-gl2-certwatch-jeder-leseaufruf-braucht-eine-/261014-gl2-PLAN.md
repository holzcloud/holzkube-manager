# certwatch: jeder Leseaufruf braucht eine Frist

Fehler in v0.6.0 und v0.7.0 (Fund der Recherche zu Phase 15, selbst nachgemessen
2026-10-14): der Daemon startet `certWatch.Run` auf `context.Background()`, und der
Talos-Client verweigert Aufrufe ohne Frist (`talos: refusing a call with no
deadline`). Auf einem laufenden Daemon wurde deshalb nie ein Zertifikat gelesen; die
Karte blieb bei "not read yet". Die Tests sahen es nicht, weil jede Test-Hilfe eine
Frist mitgibt.

## Muss wahr sein

- Jeder Aufruf von `Deps.Read` bekommt eine Frist (`DefaultReadBudget`, 20 s, über
  `Deps.ReadBudget` einstellbar), auch wenn `Run`/`Tick` mit `context.Background()` laufen.
- Ein Test liest einen echten Knoten (talossim) über einen Kontext ohne Frist.
- Beide Wächter sind gegen die entfernte Frist rot gesehen.
