## Page Structure

Route `/host`, new file `web/src/routes/host.tsx`, registered in `App.tsx`; `'/host'` added to
`ROUTES` in `web/scripts/layout-audit.mjs`; one fixture response in `web/fixtures/demo.json`.

Top to bottom, in this order on every width (D-06). Below `lg` everything is one column in
exactly this order; that is also the phone order.

1. **Header** — `h1` "Host" and one muted line under it.
2. **Notices** — zero to three, each only when it applies, in this order:
   stale reading (amber), container (slate), hardening (slate). Nothing is rendered when none applies.
3. **Device** and **Service** — two Cards, `grid gap-4 lg:grid-cols-2`, Device left.
4. **Live** — `h2` "Live" with one muted line, then the NodeHardware grid
   `grid gap-4 lg:grid-cols-[minmax(0,1fr)_20rem]`: left column Processor, Memory, Filesystems,
   Network (Memory and Filesystems side by side from `md`, `grid gap-4 md:grid-cols-2`, as
   NodeHardware's Memory/Disks row); right column the Sensors card (`h-fit`), which drops under
   the left column below `lg`.
5. **Footer line** — when the reading was taken and the poll interval.

Page container: `<section className="space-y-5">` (as `node-detail.tsx`). Live block:
`<section aria-labelledby="host-live" className="space-y-4">`.

### Header

- `h1`: `font-heading text-xl font-semibold tracking-tight` — "Host".
- Line under it: `text-sm text-muted-foreground` — see Copywriting.
- No buttons in this phase. Phase 13 adds its actions to the right of the header in the
  `flex flex-wrap items-start justify-between gap-3` shape `node-detail.tsx` already uses, so the
  header is built in that shape now with only the left half filled.

### Notices

Class strings are the existing ones from `node-detail.tsx` / `NodeHardware.tsx`, verbatim:

| Notice | When | Box |
|--------|------|-----|
| Stale reading | a later poll failed and an earlier reading exists | `rounded-md border border-amber-600/40 bg-amber-600/10 px-3 py-2 text-sm text-amber-700 dark:text-amber-300`; the whole page body below it gets `opacity-60`, as NodeHardware |
| Container | the response says the daemon runs in a container (D-17) | `rounded-md border border-slate-500/40 bg-slate-500/10 px-3 py-2 text-sm text-slate-700 dark:text-slate-300` |
| Hardening | at least one section has reason code `hardening.proc-subset` (D-03) | same slate box as Container; the fix line is a block `<code className="mt-2 block overflow-x-auto rounded-sm bg-muted px-2 py-1 font-mono text-xs">ProcSubset=all</code>` |

**Decided without asking — hardening is slate (information), not amber (warning).** The hidden
readings are a consequence of a hardening the operator chose, not a fault. Amber stays free for
Phase 12, where "Warnung" becomes a host state; spending it here now would make that state
unreadable later. Same reasoning as `HealthField.tsx`: "not readable" is muted, never alarming.

The hardening notice names the hidden readings **from the response**, not from a fixed list:
whatever sections carry `hardening.proc-subset` are listed, joined in reading order
("CPU usage, memory and swap").

### Service card (HOST-02, HOST-03)

`CardTitle` "Service". Same `dl` grid. Rows:

| Row | Value |
|-----|-------|

| Update check | see below |

**Update check (HOST-03, D-14..D-16).** Three shapes, one `dd`:

- **Recorded:** first line the outcome sentence (Copywriting), second line
  `text-xs text-muted-foreground`: "Checked {ago(checked_at)} · {toLocaleString()}", third line
  (same style) "Installed {installed} · latest {latest}" with versions in `font-mono`.
  `failed` and `rolled-back` sentences are `text-amber-700 dark:text-amber-300` (the existing
  "look at this" text colour); the others are plain `text-foreground`.
  When the status file's `installed` differs from the running version, one more muted line:
  "The update status names {installed} as installed; this process runs {version}."
- **Not recorded** (file absent): the Not recorded pattern with the server's sentence.
- **Not readable** (file present but broken): the Not readable pattern with the server's reason.

No invented time, no invented version, in any branch (D-16).

### Live section (HMON-01..04)

`h2` `id="host-live"`: `text-base font-semibold` "Live". Line under it `text-sm text-muted-foreground`:
"Read every 3 s while this page is open. Nothing on this page is stored."

**Live, not history — decided without asking.** Phase 11 draws **no curves**: no `LiveChart`, no
`RangePicker`, no `Sparkline`, and does not call `useLiveSeries`. Figures and meters only. Reason:
curves over time, and how a stretch of "not readable" appears in them (a gap, not a zero line), are
Phase 12's success criteria 1 and 2; drawing in-browser curves now would ship that contract early
and unguarded. Phase 12 adds `RangePicker` and `LiveChart` into the Processor, Memory, Network and
Sensors cards in the same places `NodeHardware.tsx` has them.

**Processor card.** Header as NodeHardware: `CardHeader className="flex flex-row items-start justify-between gap-3"`.
Left: `CardTitle` "Processor", under it muted `text-sm truncate` "{cores} cores" (model is in Device).
Right, `text-right`:
- figure: `font-semibold text-xl tabular-nums` `formatPercent(usage)`;
- under it `text-xs text-muted-foreground tabular-nums`: "load {1} · {5} · {15}" (two decimals).
Load is exact under the hardening too (D-05), so the load line is shown whenever CPU usage is
not. If CPU usage is not readable, the figure slot holds the Not readable pattern (right-aligned)
and the load line stays. If CPU usage has no baseline yet, the figure slot holds the
"Waiting for a second reading" pattern. Body: per-core usage as `Meter dense`, warn 75 danger 90,
label "CPU {i}", display `formatPercent`, grid `grid grid-cols-2 gap-x-4 gap-y-2 sm:grid-cols-4`;
omitted entirely (not zeroed) when per-core usage is not readable or has no baseline.

**Memory card.** `CardTitle` "Memory". Two `Meter`s (non-dense), no warn/danger:
- "Memory": display `formatPercent(used/total)`, detail "{used} of {total} · {cache} cache · {available} available";
- "Swap": display `formatPercent`, detail "{used} of {total}". When swap total is 0 (readable, no
  swap configured): no meter, muted `text-sm` "No swap configured."
When memory is not readable, **one** Not readable pattern covers both (they come from the same
file); no meter, no 0 %.

**Filesystems card (HMON-02, D-07).** `CardTitle` "Filesystems". One `Meter dense` per
filesystem, warn 80 %, danger 90 % of size (the NodeHardware numbers), `space-y-3`:
- label: mount in `font-mono`, then muted " {role}" where role is "root", "data directory", or
  "root · data directory" when both live on one filesystem (one row, never two identical bars);
- display `formatPercent(used/size)`;
- detail "{used} of {size} · {free} free · {device}" with device in `font-mono`.
A filesystem whose `statfs` failed shows its label line and the Not readable pattern instead of the bar.

**Network card (HMON-04, D-09).** `CardTitle` "Network", plus `Badge variant="outline"` "container"
beside it when in a container. Body: one row per physical interface, `ul` with `divide-y`:
`li className="flex flex-wrap items-baseline justify-between gap-x-4 gap-y-1 py-2 text-sm"`
- left: name in `font-mono`, muted " · up · {speed} Mbit/s" / " · up" / " · down";
- right `text-xs tabular-nums`: muted "in " `formatRate(rx)` muted " · out " `formatRate(tx)`.
Below the list, the virtual interfaces as **one** `<details className="group">` in the
`DataTable.tsx` shape, `summary` `flex min-h-11 cursor-pointer list-none items-center gap-2 text-sm text-muted-foreground marker:content-none`
with the ▶ marker; inside, the same row markup for each virtual interface. The summary is the
only interactive element on the page outside the navigation, and `min-h-11` (44 px) applies at all
widths, as in `DataTable.tsx`.
Rates without a baseline: each rate cell shows "—" and the card shows one muted `text-xs` line
"Waiting for a second reading" under the list (not per row).

**Sensors card (HMON-03, D-08).** `Card className="h-fit"`, `CardTitle` "Sensors", muted
subline "Temperatures and fans". Body `space-y-4`:
- the shared sensor list (grouped by kind with `KIND_LABEL`, severity from `temperatureLimits` and
  `severityOf`, ▲ marker + sr-only "high"/"critical" past the limit) — **without** the sparkline
  column on this page;
- "Fans" label `mb-1 text-xs text-muted-foreground`, then the shared fan rows, or the No-fan copy.
Voltages (`in*_input`) are never shown (D-08).

### Footer line

`text-xs text-muted-foreground`: "Read {toLocaleTimeString(observed_at)}, every 3 s while this
page is open. Rates are over the last {n} s." — the rates clause omitted while there is no baseline.

### Reusable readability patterns (HMON-06, D-02, D-10)

One small host-page component renders all three (the planner names it); it is the only way a
missing value is drawn on `/host`:

| Pattern | Markup |
|---------|--------|
| **Not readable** | first line `text-sm text-muted-foreground` "Not readable"; second line `text-xs text-muted-foreground` the reason sentence. For `hardening.proc-subset` the second line is the short form (Copywriting) and the full explanation lives in the Hardening notice. |
| **Not recorded** | same two lines, first line "Not recorded". |
| **Waiting for a second reading** | one line `text-sm text-muted-foreground`, no reason line. |

Hard rules: a value that is not readable is never drawn as `0`, `0 %`, `0 B`, an empty meter, or a
bare "—" without words. `formatBytes`/`formatRate` return "0 B"/"0 B/s" for non-positive input, so
the renderer must branch on readability **before** formatting. Italic is not used (HealthField's
italic reason is for stale cluster facts; here the reason is the content).

## UI Considerations

Applicable state considerations resolved: 12 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | whole page (first poll) | ✅ covered | Before the first response `/host` shows the documented "Reading the host…" line and no cards. |
| error | whole page, no reading yet | ✅ covered | A failed first poll renders the Host card with the documented error copy and `Problem`; polling continues every 3 s. |
