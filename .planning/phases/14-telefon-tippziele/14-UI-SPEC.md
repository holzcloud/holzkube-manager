# Phase 14 — UI Design Contract

> Visual and interaction contract for the phone: every control at least 44 × 44 px at 390 px,
> including what appears only after a tap, and the layout audit that goes red when one is not.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Written without questions.** The operator ordered this milestone to run without asking. Every
> choice the instructions would have put to the operator is marked **decided without asking**,
> with its reason, so it can be overturned at a glance. Sources: CONTEXT.md (D-xx), the operator's
> phone decisions of 2026-09-17 (`milestones/v1.14-REQUIREMENTS.md` V2-UI-01: tables stay
> swipeable, sizes grow only below `md`), the approved Phase 13 contract (`13-UI-SPEC.md`, "P13"),
> and the code (file named).
>
> **No new visual language, and no change above `md`.** This phase adds no screen, no colour, no
> font size and no copy on any existing screen. It changes **box sizes below `md` only**, through
> `max-md:` variants, first in `web/src/components/ui/*`, then at the few places that build their
> own controls. At 1280 px every control keeps its size and position (D-08 measures that once).

**Focal point:** unchanged on every screen. What this phase makes visible is not a new element but
the reach of existing ones: on a phone, the thumb lands on the control it aims at. The one place
the phone look changes at all is the toast's dismiss chip (below, "Toasts"), and it changes to
*less* chrome, not more.

## How a target grows (D-06, D-07)

1. **Only through `max-md:` variants.** No unprefixed size, padding or margin changes in this
   phase. A class that a reviewer can read as "this also applies at 1280 px" is a defect.
2. **In the primitive first.** A size fixed in `ui/*` is fixed on every screen; a per-screen fix
   is reserved for elements not built from `ui/*` (table above).
3. **The element's own box grows; the icon does not.** Icon sizes (`size-4`, `size-5`) are not
   touched. A ghost or transparent button grows its box around the same icon, so it looks the same
   and is hit from further away.
4. **No pseudo-element hit areas.** **Decided without asking:** D-07 allows "Pseudo-Element oder
   Padding". The audit measures `getBoundingClientRect()` of the element (or its `label`); an
   `::after` hit area does not change that box, so the audit would report the control as small and
   need an exemption, which D-09 forbids without a reason. The box itself grows, via `min-h`,
   `size` or padding.
5. **Rows grow by `min-h`, not by padding added to `py`.** A two-line item (PowerMenu items with a
   reason line, checkbox labels with a description) is already taller than 44 px and keeps its
   height; `min-h-11` only lifts the one-line case.
6. **Labels stay visible where they are visible today.** No control switches to icon-only for this
   phase; the existing `max-md:sr-only` labels (NodeActions, PowerMenu trigger) stay as they are.

### Dialogs (`ui/dialog`)

- **Close X:** `icon-sm` becomes 44 px below `md` (inventory). Its position changes from
  `top-2 right-2` to `max-md:top-0 max-md:right-0`. **Decided without asking — why the position
  moves:** at `top-2 right-2` a 28 px box has its centre 22 px from the corner; a 44 px box at
  `top-0 right-0` has its centre at the same 22 px. The X icon stays where it is on screen; only
  the tappable square around it grows, into the corner, where there is nothing else.
- **Header clearance:** `DialogHeader` adds `max-md:pr-8` (32 px). The 44 px square covers the
  top-right 44 × 44 of the dialog; with the dialog's 16 px padding, 32 px more keeps the title and
  description out from under it. Applied to every `DialogHeader`, also where `showCloseButton` is
  `false` (`SudoDialog`): **decided without asking**, a conditional would need the header to know
  about a sibling, and 32 px less line length in a dialog that has no X costs one wrap at most.
- **Footer:** unchanged. Footer buttons are `default` size (44 px) and stack full width below `sm`
  (`flex-col-reverse`), which already gives the P13 "Keep running" / confirm pair full-width 44 px
  targets.
- **Width:** unchanged (`max-w-[calc(100%-2rem)]`, 358 px at 390).

### Menus and lists (`ui/dropdown-menu`, `ui/select`)

- Items `max-md:min-h-11 max-md:py-2`; icon, gap and text size unchanged.
- `DropdownMenuLabel` and `DropdownMenuSeparator` are not controls; unchanged.
- PowerMenu's content stays `w-80` (320 px ≤ 358 px usable); its disabled items with a reason line
  are measured too (see "Disabled controls are measured").

### Mobile navigation (`Sidebar.tsx`, `AppShell.tsx`, `Header.tsx`)

- Links `max-md:min-h-11`. Fourteen links at 44 px plus gaps no longer fit 844 px with the brand
  block and the footer notices, so the drawer `nav` adds `max-md:overflow-y-auto`: **decided
  without asking** — a drawer whose last entries fall below the screen with nothing to scroll is
  the vertical form of what this audit exists to catch.
- "Open the navigation" (`Header.tsx`, `size="sm"`, icon `size-5`) is 44 × 44 already; unchanged.
- The backdrop button "Close the navigation" covers the viewport; unchanged.

### Toasts (`ui/sonner`)

- The dismiss chip is `size-6!` with a border at `top-3! right-3!`. Below `md` it becomes
  `max-md:size-11! max-md:top-0! max-md:right-0! max-md:border-transparent!`. **Decided without
  asking:** a bordered chip grown to 44 px would be a 44 px box drawn on a toast; dropping the
  border on the phone keeps the X the size it is and makes the square around it the target. Its
  centre moves by 2 px (24 → 22 from the corner). Above `md` the chip is unchanged.

## The audit's contract (MOB-02, D-01..D-05, D-08..D-11)

`web/scripts/layout-audit.mjs`, run by `task test:layout`, last step of `task ci`. Unchanged:
`WIDTHS = [390, 1280]`, height 844, `TOUCH_MIN = 44`, tap targets measured at 390 only, clipping
and sideways checks as today, fixture server from `web/fixtures/demo.json`, `LAYOUT_SHOTS`.

### Routes come from the router (D-01, D-02)

- `web/scripts/layout-routes.json`, one entry per **leaf** route of the real `routeTree`:

  ```json
  [
    { "route": "/", "path": "/" },
    { "route": "/nodes/$uuid", "path": "/nodes/m-cp-1" },
    { "route": "/kubernetes/apps/$namespace/$kind/$name", "path": "/kubernetes/apps/media/Deployment/jellyfin" },
    { "route": "/setup", "path": "/setup", "when": "before-account" },
    { "route": "/login", "path": "/login", "when": "before-session" }
  ]
  ```

  `route` is the router's `fullPath` with a trailing slash removed (`/kubernetes/` → `/kubernetes`);
  `path` is what the browser opens; a parameter route's example comes from
  `web/fixtures/demo.json`; `when` marks the two routes measured before a session, as today;
  `/wall` is a normal entry (it is measured signed in, as today). Leaves only: the `/kubernetes`
  layout route is not a page, its overview child is.
- `routeTree` moves out of `App.tsx` into a side-effect-free module that `App.tsx` and the test
  both import. The test (`web/src/layoutRoutes.test.ts`) walks it and fails with one line per
  mismatch (Copywriting, "Route guard").
- `task test:layout` runs that test **before** the browser run, so removing a route from the JSON
  ends `task test:layout` with a non-zero exit (D-10 c). `layout-audit.mjs` reads its route list
  from the JSON; the hand list `ROUTES` is deleted.

### Openers: what appears after a tap (D-03, D-04, D-05)

An explicit list in the audit, `{ name, route, widths, fixture?, open, expect }`: `open` is the
steps (clicks by accessible name, typing), `expect` the selector of what opened, `fixture` an
optional per-opener override of GET answers. After `open`, the audit waits for `expect` to be
visible, then runs the same tap-target, clipping and sideways measurement **scoped to the
`expect` element** (not the whole document: Radix leaves the page behind in the DOM, and
measuring it again would report the route's findings twice). Then Escape, and `expect` must be
gone.

The minimum list (**decided without asking** beyond D-03: the Reset dialog, the What's new panel
and one Select list are added, because each holds a control kind the D-03 set does not —
checkbox labels, chips, list options):

| Name | Route | Widths | Open | Expect |
|------|-------|--------|------|--------|
| Navigation | `/` | 390 | click "Open the navigation" | `nav[aria-label="Main navigation"]` visible after its 200 ms slide |
| What's new | `/` | 390, 1280 | (390: open the navigation first) click the version button in the sidebar | `[role="dialog"]` with title "What's New" |
| Power menu | `/nodes/m-cp-1` | 390, 1280 | click the button named "Power: …" | `[role="menu"]` |
| Power confirmation | `/nodes/m-cp-1` | 390, 1280 | Power menu, then its first **available** item | `[role="dialog"]` |
| Reset dialog | `/nodes/m-cp-1` | 390, 1280 | click "Reset" | `[role="dialog"]` containing at least one checkbox |
| Select list | `/audit` | 390, 1280 | click `#audit-action` | `[role="listbox"]` |
| Sudo dialog | chosen by the plan (D-05) | 390, 1280 | a destructive action answered `428 sudo.required` | `[role="dialog"]` with title "Confirm your password" |
| Host action dialog | `/host` | 390, 1280 | fixture: `/api/v1/host` with the helper installed and actions available; click "Restart host" | `[role="dialog"]` containing `#host-action-confirm` |

- **Red, never skipped (D-04):** a trigger not found, an `expect` not visible within 5 s, an
  `expect` still present after Escape, or **zero controls** measured inside `expect` — each is a
  failure of that opener, with its own output line. **Decided without asking — zero is red:** a
  dialog with no control in it cannot be closed by a thumb, and "measured nothing" printed as a
  count that nobody reads is the empty-output-is-green shape.
- **The count is printed** on every green opener line, as routes print theirs today.
- **The audit confirms nothing.** It never presses a confirm button and never submits the sudo
  dialog; it types into `#host-action-confirm` only if the plan needs the confirm button enabled
  to measure it (it is measured disabled otherwise, see below). Every non-GET request an opener
  sends is printed with its path and status; one to an action path (not a confirm/token path) that
  answers 2xx fails the run — the audit's proof that it never carried anything out.
- **Navigation reachability:** for the Navigation opener, if the `nav`'s `scrollHeight` exceeds
  its `clientHeight` and its computed `overflow-y` is neither `auto` nor `scroll`, that is a
  failure ("CUT OFF"): an entry below the screen is out of reach.

### Disabled controls are measured

`findSmallTargets` today skips `el.hasAttribute('disabled')`. That skip is removed. CONTEXT
"Specific Ideas": in the helper-not-installed state the four `/host` buttons are disabled "but
still measured — disabled does not mean invisible". A disabled control becomes enabled without a
layout change, and the size it has then is the size it has now. The other skips stay (D-09):
`visibility: hidden`, `display: none`, `aria-hidden="true"` on the element, zero-sized boxes (the
native `select` behind a Radix trigger), inline links in running text.

### Desktop unchanged, measured once (D-08)

With `LAYOUT_DUMP=<file>` set, the audit writes, at 1280 px, one JSON line per control on every
route and inside every opener: route, opener (or empty), tag, accessible name, and
`x, y, width, height` rounded to whole pixels. The run before the first change and the run after
the last are compared; the SUMMARY states the number of controls compared and the number that
differ, which must be **0**. Not checked in, not a permanent baseline (D-08).

### Red checks (D-10)

Three separate runs, each exit code read from `./bin/task test:layout` itself, not through a
pipe, each followed by the revert and a green run:

| # | Fault put back | Expected |
|---|----------------|----------|
| a | `max-md:h-11` removed from Button `default` | `SMALL 390px <route>` lines, exit ≠ 0 |
| b | the dialog close X back to 28 px (`max-md:size-11` removed from `icon-sm`) | `SMALL 390px <route> · <opener>` lines, exit ≠ 0 |
| c | one entry removed from `layout-routes.json` | the route guard's "in the router but not in" line, exit ≠ 0, browser run not reached |

### Hand test on a phone (D-11)

On a phone at its native width, against a daemon whose `/host` offers the actions (never the
production daemon, CLAUDE.md): open `/host` without zooming, tap "Restart host", read the dialog,
type the hostname with the phone keyboard, see the confirm button become enabled, tap
"Keep running". **Never submit.** The SUMMARY records device, browser and result; with no phone
reachable it records "not performed", never "passed".
