  <action>
Where this runs: the Pi, Node via nvm.

1. The comparer first (RED, then GREEN). Write `web/scripts/layout-dump-compare.mjs`, invoked as `node web/scripts/layout-dump-compare.mjs <before.jsonl> <after.jsonl>`. It reads both files line by line. The key is route · opener · index · tag, and x, y, width, height are compared. It prints `compared {N} controls, {K} differ`, then one line per difference with both boxes and both names (the name is information only: relative times change it between runs, Pitfall 9). A key in only one file counts as a difference and is printed as such. It exits 1 when K > 0. When either file has no lines, it exits 1 with "{file} has no controls: a dump that measured nothing compares equal to anything". Its header comment says what it is for (D-08, run once before the first class change and once after the last), and that it is not a baseline: nothing it reads is checked in. Prove the four behaviours with small JSONL files written to `$SCRATCH` (the session scratchpad, outside the repo): run each case, read the exit code from the command itself, and record it in the SUMMARY.
2. The dump in the audit. With `LAYOUT_DUMP` set, resolve it to an absolute path and refuse (throw before the daemon starts) a path inside the repository, so a dump can never become a checked-in baseline by accident. Truncate it at start. At the desk width only, for the route pass (opener empty) and for every opener (scoped to its expect element, after its animations finished), append one JSON line per control. The loop is the one findSmallTargets uses, with the same SELECTOR and the same skips: pass the one SELECTOR constant into both in-page functions as an argument rather than keeping two copies. Each line holds route (the path opened), opener name or empty, index in DOM order within the scope, tag, name (aria-label or text, 40 characters), and x, y, width, height of the element's own getBoundingClientRect rounded to whole pixels. Use the element's own box, not its label's: wrapping a checkbox in a label (14-06) must not read as a moved control. Without LAYOUT_DUMP nothing changes, and a run without it prints exactly what it printed before.
3. Update the audit's header comment: what LAYOUT_DUMP is for, and why it is a one-off measurement and not a baseline (D-08).
