<objective>
13-12 made Check for updates work and 13-13 proved an older helper refuses it safely. This plan keeps the page and the routes from offering the check to a helper that would refuse it.

The daemon cannot ask systemd which helper is installed (D-12: no D-Bus, no AF_UNIX), but it can read the installed script, as it already reads the helper's files to tell whether it is installed. 13-13 gave the script one marker line naming the orders it knows; a script without that line is the helper of 13-01, which knows exactly four. So the daemon reads that line -- bounded, and only once Detect has found the script root-owned and writable by nobody else -- and the check additionally needs its unit file. When either is missing, the check alone is off, the other four stay usable, and the routes refuse the check with 409 before anything is placed. The helper's refusal of every word it does not know stays the real lock; this is the part that keeps the page from offering what would be refused.

Output: `actions.outdated` in GET /api/v1/host, 409 `conflict.host-helper-outdated` on both host routes for the check, the contract describing both, and the check's button off with its own reason. The notice that names what to reinstall, with the commands, is 13-15's.
</objective>
