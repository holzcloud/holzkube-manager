<objective>
Close G-13-3 (13-UAT test 3; 13-VERIFICATION measured the same in the browser harness): at 390 px "Check for updates and install" runs past its button (app: scrollWidth 180 / clientWidth 173; harness: 191 / 189), the icon touching the left border.

Root cause, measured at planning time in Chromium at 390 px against the current markup: the update button's computed `white-space` is `nowrap`, its icon box starts at -0.5 px (left of the button's 0.0) and its text ends at 191.5 px in a 191-px button. The source does carry the UI-SPEC's phone class `max-md:whitespace-normal`, but it is written directly against the template literal's interpolation in `HostActions.tsx` (line ~245), so Tailwind's source scanner reads a different, invalid token and generates no rule: the built `internal/httpapi/dist/assets/index-*.css` has rules for `max-md:py-2`, `max-md:min-w-0` and `max-md:h-auto` but none for `max-md:whitespace-normal`. The button's base `whitespace-nowrap` (ui/button.tsx) therefore wins. jsdom cannot see this -- the class is in `classList` at runtime -- and the existing browser test measures only against the page's right edge, which a 191-px label in a 390-px page never reaches.

Purpose: the phone layout the UI-SPEC decided (label wraps to two lines, row neighbour stretched, >= 44 px) actually reaches the browser, held by a check that measures each button against its own box.
Output: the class list fixed, a fit check and a desktop-shape check in `host.browser.test.tsx`, both seen red, and the full gate green on the Pi.
</objective>
