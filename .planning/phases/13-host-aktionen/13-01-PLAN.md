The tracer of Phase 13: one host action -- "Check for updates and install" -- travels the whole way. The operator presses the button on `/host`, types the hostname, the confirm route issues a token bound to `host.update` on the host, the action route (session, operator, sudo window, audit) places one line in the data directory, the root helper script consumes it, runs the timer's unit through a stand-in `systemctl`, records its result in its own directory, and the page reads that result back and says what happened.

Purpose: Every hole in this phase sits between two layers (check vs. read, place vs. place, route vs. token). Proving the whole path on one action first catches a wrong seam -- a token that the action route cannot check, a file the script cannot consume, a result the daemon cannot read -- after one commit, not after eight. Every later plan widens this path; none builds a second one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST /api/v1/host/confirm, /api/v1/host/actions/* | an authenticated session asks for a root action on the machine the daemon runs on |
| daemon → data directory (host-order) | the unprivileged daemon writes the only input root will read |
| data directory → root helper script | root reads a file in a directory the unprivileged user owns |
| helper state directory → daemon → page | a file root wrote becomes a statement on the page |
| test session → production host | the round trip runs a root script; it must never reach the host's real paths or systemctl |
