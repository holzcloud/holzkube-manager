# Phase 13 — UI Design Contract

> Visual and interaction contract for the four host actions on `/host`, the dialog that confirms
> them, the order status that follows, and the notice that says the helper is not installed.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Written without questions.** The operator ordered this milestone to run without asking. Every
> choice the instructions would have put to the operator is marked **decided without asking**,
> with its reason, so it can be overturned at a glance. Sources: CONTEXT.md (D-xx), the approved
> Phase 11 and 12 contracts (`11-UI-SPEC.md` "P11", `12-UI-SPEC.md` "P12"), the existing code
> (file named), or a default (marked).
>
> **No new visual language.** The buttons are the node page's header buttons
> (`web/src/routes/node-detail.tsx`, `NodeActions.tsx`), the dialog is `PowerMenu.tsx`'s confirmation
> dialog with `NodeActions.tsx`'s typed-name field, the password step is the unchanged
> `SudoDialog.tsx`, and every box is a notice class string already in the codebase (P11 slate, and
> the emerald and red boxes of `NodeActions.tsx`'s removal dialog). Nothing new is defined.

**Focal point:** while an order is in flight, the **order status box** at the top of the notice
stack — it is the answer to "what did my click do". Otherwise the P12 focal points stand (the
Warning notice in `warn`, the Processor figure otherwise); the action buttons sit in the header's
right half, where the node page has its actions, and are not the focal point of a read-mostly page.

## Where things go on `/host`

P12's structure, with three additions (marked **new**):

1. **Header** — left half unchanged (`h1`, muted line, state line). **New:** the actions block in
   the right half of the existing `flex flex-wrap items-start justify-between gap-3` header — the
   slot P11 reserved for this phase.
2. **Notices** — **new:** order status box first → stale *or* **new:** waiting → warning →
   container → hardening → **new:** helper not installed.
3. Device, Service, Readings, footer — unchanged.

### The actions block (HACT-01..04, D-15, D-16)

Markup, right half of the header:

```
<div className="flex flex-col items-end gap-1 max-md:w-full max-md:items-stretch">
  <div role="group" aria-label="Host actions" aria-describedby="host-actions-reason"
       className="flex flex-wrap gap-2 max-md:grid max-md:grid-cols-2">
    [Check for updates and install] [Restart service]
    <span aria-hidden="true" className="w-4 max-md:hidden" />
    [Restart host] [Shut down host]
  </div>
  <p id="host-actions-reason" className="text-xs text-muted-foreground md:text-right">…</p>
</div>
```

- Order: harmless first, machine-wide last and apart (the node page's rule, `node-detail.tsx`):
  Check for updates and install · Restart service · 16 px spacer · Restart host · Shut down host.
- Each button: `variant="outline" size="sm"`, icon `aria-hidden size-4` then the label.
  Restart host and Shut down host add `className="text-destructive"` (NodeActions).
- **Phone (< md) — decided without asking:** a 2 × 2 grid, full width, labels **visible**
  (`max-md:min-w-0 max-md:h-auto max-md:min-h-11 max-md:whitespace-normal max-md:py-2` on each
  button). Row 1 is this service (update, restart service), row 2 the machine (restart host, shut
  down host). Reason: the node page hides labels below `md`, but two rotate icons side by side
  cannot be told apart without words, and these four take the page away. "Check for updates and
  install" wraps to two lines in its ~175 px cell; the grid stretches its row neighbour to the same
  height. Every button is ≥ 44 px tall and ≥ 150 px wide at 390 px.
- The reason line is rendered **only** when the buttons are off; it says the one reason that
  applies, first match wins:

  | # | Condition | Buttons | Reason line |
  |---|-----------|---------|-------------|
  | 1 | response says container (D-14) | all off | Copywriting "container" |
  | 2 | helper not installed (D-12) | all off | Copywriting "helper missing" — the notice below says what to install |
  | 3 | `roleAtLeast(me.role, 'operator')` is false (D-16) | all off | Copywriting "reader" |
  | 4 | hostname not readable (the phrase to type is unknown) | all off | Copywriting "no hostname" |
  | 5 | an order is placed or picked up and not yet answered | all off | Copywriting "order pending" |
  | — | none | all on | no line |

  All four switch together: every reason above applies to all of them.
  **Decided without asking — one reason line, not a reason per button.** A disabled button
  cannot be focused or hovered on a phone, so a `title` would be read by nobody; PowerMenu shows
  its reason under each item because its reasons differ per item, and these do not.
- The block is rendered from the host response the page already polls every 3 s (the helper,
  container and order fields the planner adds to `GET /api/v1/host`), plus the session's role. It
  never asks a second endpoint for availability.

### The confirmation dialog (HACT-05, D-08, D-09, D-15)

One `Dialog` whose content depends on the pending action; `DialogContent className="sm:max-w-md"`.
The shape is PowerMenu's confirm dialog with NodeActions' typed field, in a `<form>` so Enter
submits once the confirm button is enabled.

1. `DialogHeader`
   - `DialogTitle`: "{Label} {hostname}?" — for Restart host and Shut down host
     `className="flex items-center gap-2 text-destructive"` with `AlertTriangle aria-hidden size-5`
     (NodeActions); for the other two, plain (PowerMenu's unforced title).
   - `DialogDescription`: what the action does (Copywriting, per action).
2. Body `space-y-4 text-sm`:
   - **Consequence box.** Restart host, Restart service, Check for updates and install: the P11
     slate box `rounded-md border border-slate-500/40 bg-slate-500/10 px-3 py-2 text-slate-700
     dark:text-slate-300` with the connection sentence. Shut down host: the red box of
     NodeActions' etcd warning, verbatim, `rounded-md border border-red-600/40 bg-red-600/10 px-3
     py-2 text-red-700 dark:text-red-300` — it is the one action nothing on this page can undo.
   - **How it is carried out**, `text-xs text-muted-foreground`: the helper sentence and the
     password sentence (Copywriting). The first is there because the operator should know that
     nothing happens if the helper is not running (D-13).
   - **Typed field** (`space-y-1`): `Label htmlFor="host-action-confirm"` "Type
     `<span className="font-mono">{hostname}</span>` to confirm"; `Input id="host-action-confirm"
     autoComplete="off" autoCapitalize="none" autoCorrect="off" spellCheck={false}`.
     **Decided without asking — the three extra attributes:** a phone keyboard capitalises the
     first letter, and a hostname typed as "Example-host" never matches; no visual change.
     The phrase is `host.device.hostname.value` from the response; the server compares with
     `uname(2)` (D-08). Match is exact, as for nodes.
   - Failure: `<Problem error={…} />` from the confirm or the action route (PowerMenu).
3. `DialogFooter`: Cancel `variant="outline"`; confirm button — `variant="destructive"` for
   Restart host and Shut down host, `variant="default"` for the other two (PowerMenu's forced /
   unforced split: the machine-wide pair takes down everything on the host, the service pair only
   this service, which comes back by itself). The confirm button shows the action's icon and
   label, "Working…" while pending, and is `disabled` until the typed text equals the hostname
   and while a request is pending.

Sequence on submit (existing flow, D-08): `POST /api/v1/host/confirm` with the typed text →
token → `POST /api/v1/host/actions/{action}` → `428` opens `SudoDialog` on top, which replays →
`202` with the order id. On `202` the dialog closes and focus moves to the order status box
(`tabIndex={-1}`; `onCloseAutoFocus` prevents Radix from returning focus to the trigger, which is
now disabled). Cancel in `SudoDialog` leaves the host dialog open with its typed text, as today.
A refused request keeps the dialog open with `Problem`; the typed text is kept.

The dialog's close X is the `ui/dialog` `icon-sm` (28 px): below 44 px on a phone. Not changed
here (CONTEXT boundary: Phase 14 measures the dialog); the footer's Cancel is the 44 px way out.

### The order status box (D-05, D-13, D-15)

First in the notice stack, shown when the response carries an order that is not older than 15
minutes, or while this page holds an order it placed — until dismissed. Decided without asking:
15 minutes is long enough to cover a Pi rebooting and short enough that a reload the next day
does not greet the operator with yesterday's reboot.

Box: `role="status"`, `tabIndex={-1}`, the notice geometry `rounded-md border px-3 py-2 text-sm`
in one of three existing colour sets:

| Phase of the order | Colour set (existing) |
|--------------------|-----------------------|
| placed, picked up, started, waiting to come back | slate (P11 container/hardening) |
| back / update finished `current` or `updated` | emerald `border-emerald-600/40 bg-emerald-600/10 text-emerald-700 dark:text-emerald-300` (NodeActions removal success) |
| rejected, failed, not picked up, update finished any other outcome | red `border-red-600/40 bg-red-600/10 text-red-700 dark:text-red-300` (NodeActions etcd warning) |

Inside:
1. `<p>`: `<span className="font-semibold">{Label}</span>` " — " the phase sentence (Copywriting).
   A command in a sentence is `<code className="font-mono text-xs">`.
2. `<p className="mt-1 text-xs tabular-nums">`: "Order `{id}` · placed {time}" (`id` in
   `font-mono`, time `toLocaleTimeString`).
3. Final phases only: a `Button variant="ghost" size="sm"` "Dismiss" at the end of the box
   (`mt-2`; 44 px below `md`). Dismissed per order id for the life of the page. No dismiss while
   the order is under way — the buttons are off for it anyway (reason 5).

Phases, as the page derives them (`id` from the `202`, then the response's order and service
fields):

| Phase | When |
|-------|------|
| placed | order file present, no result for this id |
| picked up | file gone, no result yet |
| started / rejected / failed | the helper's result for this id (D-05) |
| not picked up | the daemon withdrew it after 10 s (D-13) |
| waiting to come back | the latest poll failed **and** the order is started (or picked up) with action reboot, poweroff, restart-service or update |
| back | a poll answers again and the process start (restart-service, update) or the boot time (reboot, poweroff) is later than the order |
| update finished | update: the update status's `checked_at` is later than the order |

The phase sentence is the only thing in the box that changes, and the box's `role="status"` is
polite, so each transition is announced once; nothing in it ticks.

### Waiting for holzkube-manager to come back (D-15)

While the phase is "waiting to come back", the P11 **stale notice is replaced** by the waiting
notice — same position, the slate box, not amber (it is expected, not a fault). Everything else of
P11's stale handling stays: the body below keeps `opacity-60`, the last reading stays on screen,
and the page keeps polling every 3 s (`HARDWARE_POLL_INTERVAL_MS`, `retry: false` — unchanged).
No error page, no reload. When a poll answers again, the waiting notice goes and the status box
moves to "back".

This applies whether the order came from this browser or not: the condition is the order in the
last reading, so a second operator's open `/host` also says "waiting", not "did not answer".

A poll that fails with **no** order under way is still the P11 amber stale notice — the two are
never shown together.

### Helper not installed (HACT-07, D-12)

Last in the notice stack, shown when the response says the helper is missing and the daemon is
**not** in a container (the container notice already says why there are no actions there).

Box: the P11 slate box. Inside:
1. `<p className="font-semibold">` heading (Copywriting).
2. `<p className="mt-1">` the explanation (Copywriting).
3. `<ul className="mt-2 space-y-1">` one `<li>` per missing item **from the response, in the
   server's order** — the path in `font-mono` (`break-all`), then " — " what it is and which
   `deploy/` file it comes from (Copywriting). Only what is missing is listed.
4. `<pre className="mt-2 overflow-x-auto rounded-sm bg-muted px-2 py-1 font-mono text-xs">` with
   the install commands, one per line — the P11 fix-line style as a block. **Selectable text, no
   copy button** (decided without asking, the rule already written in `routes/accounts.tsx`
   `TokenOnce`: the clipboard is refused outside a secure origin, which is where this product often
   runs). The commands must be the ones in `deploy/HOST-HELPER.md`, byte for byte; the planner
   makes one the source of the other or a test compares them.
5. `<p className="mt-2 text-xs">` the closing line (Copywriting).

No button, no dismiss. The notice goes when a poll says the helper is installed.
