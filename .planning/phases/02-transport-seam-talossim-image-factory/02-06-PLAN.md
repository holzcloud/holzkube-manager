multi-select over that response — **there is no text input for an extension name**, which is

previously selected extension that is absent from the new version's catalog is removed from
the selection and reported to the operator by name, because an extension valid at one version
may not exist at another and a silently carried-over selection produces a schematic that is
un-buildable at exactly the moment it matters.

Kernel arguments and META entries are free-form by nature — they are operator-authored values,
not names from a catalog — and each is a repeatable row with an add and a remove control.

| T-02-34 | Information disclosure | kernel args and META in the audit archive | high | mitigate | the allowlist for `schematic.create` permits only the schematic name and the Talos version; every other parameter falls through to the fail-closed default and is written redacted, asserted by a `redact_test.go` case |
| T-02-35 | Tampering | an unvalidated extension name reaching the Factory | high | mitigate | the create handler validates every name against the version-scoped catalog and returns a `validation` problem before any POST; a test asserts the fake Factory recorded zero POSTs on that path |
