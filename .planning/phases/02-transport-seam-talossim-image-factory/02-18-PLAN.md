<objective>
Close G-02-23, a user decision recorded on 2026-08-30: re-root the problem-type taxonomy at
`urn:holzkube-manager:problem:`.

Purpose: `ProblemBaseURI` and all thirteen `Type*` constants are rooted at
`https://holzkube.dev/problems/`. That hardcodes a vendor domain into a contract AGPL redistributors
must ship unchanged, and it looks like a promise that a page exists at that address. Nothing
dereferences it — the UI branches on `code` (`problem.ts:7`, `:98`) and no comparison against a type
URI exists anywhere in the codebase — so the domain buys nothing and costs the redistribution story.
RFC 9457 permits non-HTTP URIs, and a URN is deployment-independent by construction.

The decision has a shape as well as a value, and the shape is the part that is easy to get wrong.
A per-deployment configurable base was considered and **rejected**: two installations would emit
different `type` values for the same error, so every third-party client would need a per-install
special case. It solves a problem that does not exist — nothing fetches the URI — at the cost of the
one property the field has. The taxonomy stays closed, stable and identical everywhere;
`problem.go`'s existing sentence, that clients may match on these and they never change, still holds
and is the reason this change happens once.

Sequencing: this lands **before** the repository-wide holzkube to holzkube-manager rename and
already carries the post-rename name. The rename's PROTECTED list guards `holzkube-manager` first,
so the URN is not double-renamed — which is exactly why no other occurrence of that string may be
introduced here.

Output: one base constant, thirteen types derived from it, six fixture sites moved with it, a
contract that says what a type URI is for, and a test proving nothing depends on its value.
</objective>

Re-root every type in the contract and add the paragraph the contract has never had.

That paragraph says three things, in the register the file already uses. A `type` is an
**identifier**: clients match on it, and nothing fetches it. It is deliberately **not
dereferenceable** — there is no page at that address and none is promised, which is a property a URN
makes obvious and an https URL actively misrepresented. And it is **deployment-independent**: every

rejected alternative is stated in one sentence so the next reader finds the decision rather than the

this use — RFC 9457 asks for a URI, not a registered URN namespace, and the value is an opaque
identifier either way — but a contract that says "URN" without that sentence invites a reader to
assume a registration that does not exist. One clause is enough.

declaration that the taxonomy is closed. This is a change to one field's spelling and to the
explanation of what that field is for.
