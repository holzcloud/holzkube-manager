<objective>
Build the hand-rolled Image Factory HTTP client (D-01) and prove it end to end: compose a
schematic, precompute its ID locally, validate every extension name against the
version-scoped catalog, POST it, confirm the returned ID matches the precomputed one, and
mark it usable only after a model-build probe says it actually builds.

Purpose: track (b) has zero Talos dependency — it is the ROADMAP's second parallel track and
runs concurrently with 02-01. It also carries the phase's most-documented trap: the Factory
returns success for a schematic referencing an extension that does not exist, so
"Schematic created ✓" after a POST is a lie (PITFALLS.md P9, verified by live experiment).

Output: `internal/imagefactory`, the minted `upstream` problem family, and the contract row
that makes an unreachable upstream reportable instead of anonymous.
</objective>

## Flagged assumptions

1. **Probe-report rows owned by this plan: FACT-01, FACT-02, FACT-06.** All three returned
   `unclassified` / `unresolved` from the deterministic edge probe. This is a **classifier
   language miss** — the probe classifies on English keywords and `REQUIREMENTS.md` is
   German — not evidence that these requirements have no edges. Each was hand-derived into
   `must_haves.truths` above rather than dropped.
2. **The two research documents disagree on the POST status code.** `STACK.md` records
   `201 Created` for `POST /schematics`; `PITFALLS.md` records `HTTP 200` for the same
   endpoint in the bogus-extension experiment. The plan accepts both. If the executor
   observes only one in the live test, record which — but do not narrow the client to it.
3. **The exact canonical serialisation the Factory hashes is not recorded in research.**
   Only two (payload, id) pairs are. The fixtures are therefore the specification: if the
   implementation disagrees with a fixture, the implementation is wrong. If neither can be
   reproduced, stop and report rather than adjusting the fixtures — a locally computed ID
   that does not match the Factory's is worse than no local computation, because FACT-06
   exists to detect "this schematic already exists" without a round trip.
4. **`STACK.md`'s "an official Go client exists. Do not hand-roll HTTP." is overruled by
   D-01** and must not be reinstated: `siderolabs/image-factory` requires machinery at a
   `v1.14.0-rc.2` pseudo-version and lists the Talos root module in its direct requires,
   which would move holzkube off its pin and pull the root module into a graph the
   package-level depguard does not cover.
5. **This plan owns `docs/api-contract.md` in wave 1.** Plan 02-04 (wave 2) appends the
   schematics endpoint section, plan 02-06 (wave 3) amends the Route Registration Rule and
   plan 02-07 (wave 5) appends the dry-run status field. No two plans in the same wave touch
   this file.

|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Denial of service | `client.go` response decoding | high | mitigate | every response body is read through an `io.LimitReader` with a named cap before decoding, for the reason `handlers.go:19-27` already states about inbound bodies; a test asserts an oversized body is refused |

| T-02-12 | Denial of service | a hung upstream connection | medium | mitigate | the client owns an explicit `*http.Client` with a named `Timeout`; `http.DefaultClient` (no timeout) is not used, and a test asserts a timed-out call returns and leaks no goroutine |
| T-02-13 | Tampering | a schematic marked usable that cannot build | high | mitigate | usability is decided by the model-build probe (FACT-02), never by the POST's status code |
