<objective>
Close G-02-6: an input holzkube itself refuses must be reported as an input problem naming the
field, and must be refused at the input before it is ever sent.

Purpose: a control character in a kernel argument is rejected by `representable()` in holzkube's own
canonical serialiser, before anything crosses the network — measured at 18.658ms, which is not a
network round trip. The operator was shown "The Image Factory did not answer usably: creating the
schematic." at HTTP 502, a sentence that blames a third party, invites a retry that can never
succeed, and never names the field. The cause is structural: `Author` returns the refusal with an
empty `Authored.ID`, so `createSchematic` routes it through `createProblem` into the
upstream-unavailable presentation reserved for the Factory's own failures.

Output: a typed refusal that names the document path and the entry, a handler that maps it to a 400
naming the request field, an input that refuses the character class before Create is enabled, and a
create error that stops outliving the form state that produced it.
</objective>

## Interaction with the open probe-budget decision

Nothing here touches the probe, its budget, its state or the create route's shape. One boundary is
worth stating because it looks adjacent:

- **This does not split the create route.** Option 1 in `02-DECISION-probe-budget.md` would have
  `POST /api/v1/schematics` answer 201 immediately. That option's 201 body and its `warnings`
  contract are unaffected by this plan, and the new 400 sits strictly before the point at which the
  two options diverge — the refusal is raised by `Schematic.ID()` before the catalog fetch, before
  the POST and long before any probe. Either option can be adopted afterwards without revisiting
  this branch.
