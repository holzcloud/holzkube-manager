<scope_decision>
## W-2: this plan was split, not accepted as oversized

The plan checker flagged this plan at 18 files / 3 tasks / ~95k projected tokens — the largest
in the phase, and the one that owns TRANS-06 🚫, the phase's only release blocker. ROADMAP
ordering constraint #1 makes it a correctness dependency for every phase ≥ 3, so degradation
here is the most expensive degradation this phase has available.

**Decision: split.** The former task 2 — the full `MachineService` subset, the in-memory COSI
state, the three streams and the method-drift guard — moved out to plan **02-08** (wave 2,
`depends_on: ["02-01"]`). What stays here is the tracer and the seam proof.

The deciding argument is not the total size, it is *where in a context window each task lands*.
Run as three tasks, the seam proof — two `Dialer`s and two `DiscoverySource`s against one call
site, which is the whole of TRANS-02 — went last, at roughly 85% of the window, behind the
heaviest task in the phase. It now runs second, at roughly 50%. The tracer-first shape is
intact: task 1 is still the end-to-end slice, task 2 still expands outward from it, and this
plan is independently verifiable end-to-end without anything 02-08 adds.

Two things get better rather than worse. `Hostname` moves into task 2 here, so the plan that
declares the `Probe` contract is the plan that makes the sim satisfy it. And 02-08's
method-coverage guard walks `internal/talos` for machinery-client call sites *after* this plan
has written `dial_direct.go`, so it sees more real call sites than it could have seen inside
this plan.

The cost, recorded honestly: the phase goes from four waves to five, and plan 02-03 gains a
declared dependency on 02-08. Both are in frontmatter, not left to ordering luck.
</scope_decision>

The assumption-delta detector fired (`kind: pluralization`, term `second`). Its literal
trigger is a false positive — the word comes from the scenario name
`second_bootstrap_returns_AlreadyExists`. A genuine delta exists anyway and is decided here.

**Primary noun: `Target`** — a machine's stable identity (`ClusterID` + `MachineID`),
not its address.

**Decision: `promote`.** Everything above the seam speaks `Target`. `Addr` is demoted to
a *hint field on `Target`*, never identity: `Dialer.Resolve` maps identity → something
dialable, and a tunnel transport later resolves the same `Target` to an overlay address
with no change above the seam. The alternative — keeping the address as the primary key
and adding identity alongside — would let the `ip_changes_on_reboot` scenario (TRANS-07)
silently answer for the wrong node, which is exactly the failure the promotion prevents.

A second, smaller delta is already decided by D-06: cluster and maintenance clients are
**two types**, not one type with a mode flag — also a promote, not an add-alongside.

**Companion invariant test (accepted):** `TestNoAddressAboveTheSeam` in
`internal/talos/seam_test.go` — the same shape as the existing `TestNoDirectFileAccessOutsideFsstore`
AST guard — asserting that no production package outside `internal/talos` constructs a
`host:port` string for a node or imports `machinery/client` directly.
