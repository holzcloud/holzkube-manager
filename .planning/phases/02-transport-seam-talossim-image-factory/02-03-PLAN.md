## The expected-behaviour table this plan owes

`02-CONTEXT.md` `<specifics>` states that the nine scenarios are enumerated and closed, and
that what is **not** specified anywhere is the client's defined behaviour per scenario.
This is that specification. It is normative for plan 02-05, which asserts the production
client against it, and it is the content of both `scenario.go`'s registry and `docs/talossim.md`.

| Scenario | What the sim does | Defined client behaviour |
|---|---|---|
| `go_silent(90s)` | accepts the TCP connection and completes the TLS handshake, then writes no response byte for the configured duration | every non-stream call fails at **its own class deadline** (probe 5 s, fast read 10 s, mutation 30 s) and never at 90 s; a concurrent call to a second target is unaffected; after the configured consecutive-failure count the per-node breaker opens |
| `reject_apply` | `ApplyConfiguration` returns `codes.InvalidArgument` with a message | the call is **not retried** — it is in the mutation class — and surfaces as a distinguishable typed failure carrying the upstream message; the breaker records no failure, because an answered call is not a transport failure |
| `second_bootstrap_returns_AlreadyExists` | the first `Bootstrap` succeeds; every later one returns `codes.AlreadyExists` | the client surfaces `AlreadyExists` as its own outcome, never retries it, and never reports success; this is the exact case the retry allowlist exists to prevent |
| `flap_connection` | closes and reopens the listener on a configurable cycle | a fast-read call retries at most twice (200 ms → 800 ms, full jitter), inside the **original** deadline, and succeeds if a window opens; a mutation fails on the first `Unavailable`; a stream is never restarted |
| `slow_log_consumer` | `Logs` produces faster than the consumer reads until the send blocks | the client does not deadlock; the caller's context cancellation tears the stream down within 1 s; the 60 s idle timeout applies to *no data flowing*, not to a blocked send |
| `ip_changes_on_reboot` | after a simulated reboot the sim listens on a new address and the old one refuses connections | `Dialer.Resolve` is consulted again on the next call, because `Target.Addr` is a hint and `MachineID` is identity; a stale address yields `Unavailable`, never an answer attributed to the wrong node |
| `etcd_down` | every `Etcd*` RPC returns `codes.Unavailable`; `Version` and `Hostname` still answer | node-level calls keep working; etcd calls fail distinguishably; the breaker does **not** open, because the node is reachable and only one subsystem is not |
| `k8s_down` | the k8s-related COSI resources are absent and the k8s service reports not-running in `ServiceList` | a COSI read for a k8s resource returns a not-found-shaped result rather than an error; the node stays reachable and the failure is attributable to Kubernetes, not to the transport |
| `version_out_of_supported_range` | `Version` reports a Talos version outside the supported range v1.12–v1.14 | `NewClusterClient` refuses with a named error identifying the observed version and the supported range, rather than proceeding against an untested API surface |

`type Scenario struct { Name ScenarioName; Duration time.Duration; Cycle time.Duration;
Version string }` — one struct carrying every scenario's parameters, so a caller writes
`Inject(Scenario{Name: ScenarioGoSilent, Duration: 90 * time.Second})` and the zero value of
an unused field is not a trap. Unused parameters for a given scenario are documented as such.

`var Registry = map[ScenarioName]Definition{…}` where
`type Definition struct { Sim string; ExpectedClient string; Defaults Scenario }`. `Sim`
and `ExpectedClient` are the two prose columns of the table above, verbatim. Copy
`internal/audit/redact.go`'s doc-comment discipline: state why the table exists and what its
default direction is — a scenario with no registry entry is a missing specification, not a
no-op, and `Inject` refuses it.

`func (s *Server) Inject(sc Scenario) (clear func(), err error)` — validates against the
registry, stores the active scenario under the server's existing mutex, and returns a
`clear` closure that restores the previous state. Injection is a mutation of an
already-running sim: no restart, no re-listen, no client reconnect, because a test that has
to reconnect proves nothing about a fault appearing mid-session. `func (s *Server) Active()
[]Scenario` exposes what is currently injected so a test can assert the sim's own state.
No background goroutine owns scenario lifetime — follow `ratelimit.go`'s argument: a
goroutine would need a lifetime, a shutdown path and somewhere to be stopped in every test.

`talossim.go`: expose the single accessor every service method consults before answering, so
the fault check is one function rather than nine scattered conditionals.

`docs/talossim.md`: the operator- and reviewer-facing document. It carries the same nine-row
table, plus a short section stating the two rules this fake lives by — it embeds
`UnimplementedMachineServiceServer` so that missing coverage is a test failure rather than a
zero value, and it reproduces documented failure shapes rather than convenient
approximations. Add a paragraph recording the `Client.EventsWatch` hazard explicitly: it
drops undecodable events and returns **nil** on `io.EOF`, `codes.Canceled` and
`codes.DeadlineExceeded`, so `go_silent` and `flap_connection` look like clean success to a
caller that only checks the error — every assertion in this phase is therefore built on
timing, on call counts observed at the sim, or on the connection state, never on a bare
`err != nil`.

`scenario_test.go` (this task's share): `TestRegistryCoversTRANS07` asserts the registry's
key set equals the nine names, failing with the missing or extra name; and
`TestDocumentedScenariosMatchRegistry` parses the table in `docs/talossim.md` and asserts its
row set equals the registry's key set, so the document cannot rot into a lie.

Implement the five scenarios whose fault lives in the connection or in timing.

`go_silent(90s)`: the sim accepts the connection and completes the TLS handshake — that
matters, because a refused connection and a silent one produce different client behaviour —
then blocks every RPC handler for `Scenario.Duration` or until the server closes, whichever
comes first. The handler must respect the server's shutdown so a test cannot hang the suite.
Default duration 90 s per TRANS-07, but the test injects a short duration and asserts the
*client's* deadline fires first, which is the property under test.

`flap_connection`: close the listener, wait `Scenario.Cycle`, re-listen on the **same**
address, repeat. Existing connections are severed on close; the address must be reusable, so
hold the port explicitly rather than re-binding to `:0`. Expose an observation the test can
read — a counter of open/close transitions — so a flap is provable without relying on a
client error.

`slow_log_consumer`: stall the `Logs` emission channel so the send blocks once the consumer
stops reading. The sim records that its send is blocked and for how long; that record, not a
client error, is the assertion. A test consumes a few messages, stops reading, asserts the
sim observes a blocked send, then cancels the caller's context and asserts the stream is torn
down within 1 s.

`ip_changes_on_reboot`: `Reboot` (or an explicit injection) makes the sim stop listening on
its current address and start listening on a new loopback address, exposed through the
existing `Addr()`. The old address must actively refuse connections rather than time out —
those are different client-observable outcomes and only the refusing one models a released
port. The sim records both addresses so a test can assert the change without guessing.

`version_out_of_supported_range`: the sim's `Version` reports the version carried in
`Scenario.Version`, defaulting to something outside v1.12–v1.14. In `internal/talos/client.go`,
`NewClusterClient`'s D-05 liveness probe gains the range check: a version outside the
supported range is a named refusal identifying the observed version and the supported range,
not a warning. The supported range is a single exported constant pair in `internal/talos`,
referenced by both the check and its test, so a range change is one edit.

Assertions for all five: build on timing bounds, on the sim's own counters, or on connection
state. Not on `err != nil` alone, for the reason `docs/talossim.md` now records.

Implement the four scenarios whose fault lives in RPC semantics, then close the gate.

`reject_apply`: `ApplyConfiguration` returns `status.Error(codes.InvalidArgument, …)` with a
message shaped like a real Talos validation rejection. The sim counts how many times
`ApplyConfiguration` was called — that counter is what proves the client did not retry.

`second_bootstrap_returns_AlreadyExists`: the sim's node state already records whether it is
bootstrapped. The first `Bootstrap` sets it and returns success; every later call returns
`status.Error(codes.AlreadyExists, …)`. This is a state transition, not a counter trick, so
that a client which reconnects still sees the second call rejected. The sim exposes the
bootstrapped flag for assertion.

`etcd_down`: every `Etcd*` method returns `codes.Unavailable`, while `Version`, `Hostname`
and `ServiceList` answer normally. The asymmetry is the point: it distinguishes "the node is
gone" from "one subsystem is gone", which is what stops the breaker from opening on a
reachable node.

`k8s_down`: the k8s-related COSI resources are removed from the in-memory state and
`ServiceList` reports the kubelet-shaped entry as not running. A COSI read for a k8s resource
therefore returns a not-found-shaped result rather than a transport error.

Completeness gate, in `scenario_test.go`: `TestEveryScenarioIsImplemented` iterates the
registry, injects each scenario in turn against a fresh sim, exercises the RPC or the
connection the `Sim` column names, and fails when the sim's behaviour is indistinguishable
from the un-injected baseline. A scenario that is registered, documented and inert is the
worst outcome available here — it makes plan 02-05's contract suite pass against nothing —
so the gate must compare against a baseline rather than merely assert no panic. Record in
the SUMMARY that the gate was observed to fail once, with an implementation deliberately
disabled, before being restored.

## Flagged assumptions

1. **Probe-report row owned by this plan: TRANS-07** — returned `unclassified` /
   `unresolved` from the deterministic edge probe. **Classifier language miss**: the probe
   classifies on English keywords, `REQUIREMENTS.md` is German. Hand-derived into
   `must_haves.truths` above rather than dropped.
2. **The expected-behaviour table is authored here, not inherited.** `02-CONTEXT.md`
   `<specifics>` states explicitly that the client's defined behaviour per scenario is
   specified nowhere. The table above is the first statement of it. It is derived from the
   deadline policy in `02-CONTEXT.md` `<deadline_policy>`, which is itself marked **PROPOSED,
   awaiting confirmation** — see plan 02-05's checkpoint. If that checkpoint changes a
   deadline class or the retry allowlist, the `ExpectedClient` column changes with it and
   this plan's registry must be updated in the same commit.
3. **`version_out_of_supported_range` puts a range check into `internal/talos/client.go`,
   which plan 02-01 created.** This is the one code file outside `internal/talossim` this plan
   touches, and it is declared in `files_modified` rather than left implicit. Plan 02-05 also
   modifies that file, in wave 4 — after this plan — so the edits do not race.
4. **`ip_changes_on_reboot` rebinding to a new loopback address is an approximation of a
   DHCP change.** A real node keeps its identity and changes its address on the same
   network; the sim changes both the port and the address inside `127.0.0.0/8`. The
   property under test — that `Target.Addr` is a hint and `MachineID` is identity — is
   preserved. Recorded so a later reader does not mistake the mechanism for the claim.
5. **This plan depends on 02-08 as well as 02-01, after the W-2 split of 02-01.** The methods
   these scenarios intercept, the emission channel `slow_log_consumer` stalls and the COSI
   resources `k8s_down` removes are all written by 02-08 in wave 2. The dependency is declared
   rather than inferred from wave order, so re-slicing the phase cannot silently break it.
