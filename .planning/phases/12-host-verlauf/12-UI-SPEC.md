# Phase 12 — UI Design Contract

> Visual and interaction contract for the history, warning and state that `/host`, the
> navigation and the wall gain in this phase. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker.
>
> **Written without questions.** The operator ordered this milestone to run without asking.
> Every choice the instructions would have put to the operator is marked **decided without
> asking**, with its reason, so it can be overturned at a glance. Sources: CONTEXT.md (D-xx), the
> approved Phase 11 contract (`11-UI-SPEC.md`, "P11"), the existing code (file named), or a
> default (marked).
>
> **No new visual language.** This phase draws history with the charts a node already has
> (`LiveChart`, `RangePicker`, `Sparkline`, `useChartRange`, `merge`, D-05), colours the wall tile
> with the wall's existing `TILE_COLOURS` (D-14), and spends the amber that P11 deliberately kept
> free for exactly this state. The only new piece is a three-shape state mark, built from an
> existing token set and an icon the `Meter` already uses.

**Focal point:** when the host is in **Warning**, the amber Warning notice under the header — it is
the one thing on the page that says what is wrong and by how much. Otherwise (Healthy / Not
readable) the P11 focal point stands: the Processor figure.

## The state mark (HOST-04, D-10, D-13)

One component, three shapes, so the state survives greyscale and colour blindness (green/amber is
the classic confusion pair):

| State | UI word | Shape | Markup |
|-------|---------|-------|--------|
| `ok` | Healthy | filled dot | `<span className="inline-block size-2 shrink-0 rounded-full" style={{ background: 'var(--viz-ok)' }} />` |
| `warn` | Warning | triangle | `<AlertTriangle aria-hidden="true" className="size-3.5 shrink-0" style={{ color: 'var(--viz-warn)' }} />` |
| `unknown` | Not readable | hollow ring | `<span className="inline-block size-2 shrink-0 rounded-full border border-muted-foreground" />` |

- All three sit in a fixed `inline-flex size-4 shrink-0 items-center justify-center` box, so a
  change of state never moves the text beside it.
- The shapes are `aria-hidden`; the mark carries `<span className="sr-only">` text: "healthy",
  "warning", "not readable" (sidebar form: " — healthy" etc., so the link reads "Host — warning").
- `title` = the server's summary sentence (desktop hover only; never the only place it is said).

**Decided without asking — three shapes, not three coloured dots.** D-13 says "a dot in the three
colours with screen-reader text". The screen-reader text covers non-sighted readers, but not a
sighted reader who cannot tell `--viz-ok` from `--viz-warn`; the project's rule is "severity is
never colour alone" (P11 Color). The triangle is the icon `Meter` already shows for "high", so it
is not a new sign.

## Where the state is shown

### Navigation (D-13)

- `Sidebar.tsx`: the "Host" entry gets `HostStateMark` in the slot where a `P{n}` chip would sit
  (after `<span className="flex-1">`). No chip, no text beside it, no count.
- Data: `useQuery({ queryKey: ['host'], queryFn: api.host, refetchInterval: 30_000, retry: false })`
  inside the sidebar — the **same query key** as `/host`, so while `/host` is open its 3-s poll
  updates the mark and no second request shape exists; elsewhere it refreshes every 30 s
  (decided without asking: the sidebar is on every page, and a 3-s poll of a whole host reading
  on every screen is waste. Planner must confirm that an extra caller of `GET /api/v1/host` does
  not shorten the rate baseline `/host` shows — if it does, the sidebar reads a lighter field
  instead of the whole reading, not a second endpoint).
- Before the first answer: **no mark** (nothing has been asked yet; a grey ring would claim "not
  readable"). Latest poll failed: `unknown` with sr-only " — not readable, holzkube-manager did
  not answer" (the wall's rule: an unanswered question is not an answer; never keep a green dot
  from an earlier reading).
- The entry's tap target is unchanged (the sidebar's existing sizing; Phase 14 owns MOB-01 for
  the navigation). The mark adds no control.

### `/host` header — the state line

Directly under P11's muted header line, still in the left half of the
`flex flex-wrap items-start justify-between gap-3` header (Phase 13's actions keep the right):

`<p className="mt-2 flex flex-wrap items-center gap-x-2 gap-y-1 text-sm">`
- `HostStateMark`;
- the word, `font-semibold`, wrapped in `<span aria-live="polite">` — only the word is live, so a
  temperature that changes every 3 s is not re-announced, but a change of state is;
- the summary, `text-muted-foreground`, from the server (Copywriting).

The state line is **not** dimmed when the reading is stale (it is in the header, above the stale
notice, which explains its age) — same as P11's header.

### `/host` — Warning notice (HMON-07, D-09)

Shown only in state `warn`. Position: in the P11 notice stack, **after** the stale notice and
**before** container and hardening:
stale (amber) → **warning (amber)** → container (slate) → hardening (slate).
Stale stays first because it says the warning itself may be old.

Box: the P11 amber class string, verbatim —
`rounded-md border border-amber-600/40 bg-amber-600/10 px-3 py-2 text-sm text-amber-700 dark:text-amber-300`.
Inside:
1. heading `<p className="flex items-center gap-2 font-semibold">` with `AlertTriangle`
   `aria-hidden size-4 shrink-0` and the heading copy — the icon is what tells this box from the
   stale box beside it;
2. `<ul className="mt-1 space-y-1 tabular-nums">`, one `<li>` per warning sentence from the
   server, **in the server's order** (worst first; the browser never re-sorts or re-words);
3. when some rated values are also unreadable (warn beats unknown, D-10):
   `<p className="mt-1">` "Also not readable: {reasons}";
4. `<p className="mt-1 text-xs">` the threshold rule (Copywriting).

No button, no dismiss, no link. The notice goes away when the server stops saying `warn`.

Per-value marks stay where they are and must agree with the notice: the sensor row's ▲ (server
`warn_c`/`danger_c`) and the filesystem meter's amber (80 % of `used + available`, df's
denominator — the server's disk warning must use the same denominator, or meter and notice
disagree at the boundary).

### Wall — the host tile (D-14)

- The wall response's new `host` field (name, state, reason) is drawn as the **first tile of the
  "Nodes" section**, by the existing `Named`: the host tile is prepended to the tiles `Named`
  renders, so its size class (count and longest name) is computed together with the nodes' and
  all tiles in the section stay one size.
- Tile: `TILE_COLOURS[state]` (`ok` green-700, `warn` amber-700, `unknown` zinc-600 — decided
  without asking per CONTEXT discretion: yes, `unknown` is the existing grey). First line the
  host's name (`break-words font-semibold`, as every tile); second line
  `manager · {reason}` in the tile's existing `truncate opacity-80` line.
- `data-row`, `data-state={state}` as every tile, plus `data-kind="host"` so tests and the layout
  audit can find it.
- **No trend sparkline** on the host tile, even if a node shares its name — the wall's `host`
  carries no trend (D-14: name, state, reason — no address, no version).
- The headline and its counts are **unchanged**: "{n} nodes" counts `wall.nodes`, not the host
  tile, and the host never enters `summary` (D-14). The host is **not** added to "Needs
  attention" (decided without asking: it is always on screen as the first tile, so naming it a
  second time would double it; and the headline is the cluster's answer).
- `host` absent or null in the response (older daemon, or a daemon that has no host reading) →
  no host tile. Never a placeholder tile.
- Wall links see the same tile (the wall response is all a link can open).

## Copywriting Contract

English, sentence case. `{braces}` come from the response. Documentation values only
(`manager-01.homelab.example`, `example-host`). Warning, summary and wall sentences are **written
by the server** (D-06: one implementation for page, navigation and wall); the browser prints them
verbatim. The exact sentences are decided here (CONTEXT discretion).

| Element | Copy |
|---------|------|
| Primary CTA | None — `/host` stays read-only (actions are Phase 13). The controls this phase adds are the range buttons "Live", "1 h", "6 h", "24 h" (existing labels). |
| State words (page, sidebar `title`) | Healthy · Warning · Not readable |
| State words (sr-only in the sidebar) | " — healthy" · " — warning" · " — not readable" · " — not readable, holzkube-manager did not answer" (latest poll failed) |
| Summary, `ok` | Temperatures and filesystems are below their thresholds. |
| Summary, `ok`, no temperature sensor (D-11) | Filesystems are below 80%. This machine reports no temperature sensors, so it is judged by its filesystems alone. |
| Summary, `warn` | 1 threshold crossed. / {n} thresholds crossed. |
| Summary, `unknown` | the reasons, each its own sentence, joined by a space (below) |
| Reason: temperatures unreadable | Temperatures could not be read: {server reason}. |
| Reason: filesystem usage unreadable | Usage of {mount} could not be read: {server reason}. |
| Reason: old snapshot (D-11) | The last reading is older than 45 s. |
| Warning notice heading | Warning — 1 threshold crossed / Warning — {n} thresholds crossed |
| Warning, temperature | {sensor} {82.1} °C ≥ {80} °C |
| Warning, temperature past danger | {sensor} {112.0} °C ≥ {110} °C, critical |
| Warning, filesystem | {mount} {91}% used ≥ 80% |
| Sensor name in a warning | the chip, then the label unless the label is a bare `temp<N>` and it is the chip's only sensor — "cpu_thermal", "k10temp Tctl", "nct6798 temp2" |
| Number format in a warning | temperature with one decimal, threshold without decimals when whole; percent as df prints it (whole number, rounded up — the figure the Filesystems meter shows) |

| Wall tile, line 2 | manager · healthy / manager · {first warning} / manager · {first warning} and {n} more / manager · not readable |
| Wall tile name | the hostname; "holzkube-manager host" when the hostname is not readable |
